Cloudflare والنشر

Worker يستقبل الطلبات وDurable Objects تنسّق مسارات الأجهزة. خدمة DeskSwarm الحالية تظل على Linux لتشغيل Docker والـAgents وحفظ البيانات.

ابدأ بسرعة — من السيرفر للنشر

ابدأ بسيرفر Linux عليه DeskSwarm شغّال. ربط سيرفر Docker وحده لا يثبّت لوحة التطبيق عليه؛ تقدر تختار اللوحة المحلية الحالية بدلًا منه.

  1. ١. اختَر سيرفر Linux

    اربطه عبر SSH أو NetBird، أو استخدم Docker المحلي، ثم اكتشف خدمة DeskSwarm.

    ربط سيرفر Linux / NetBird
  2. ٢. اربط حساب Cloudflare

    أدخل API Token، اكتشف الحساب واختر اسم Worker. عنوان Linux يتجهّز تلقائيًا بعد إنشاء Tunnel.

  3. ٣. أنشئ Tunnel وانشر التطبيق

    حمّل الدومينات، اختر عنوانًا جديدًا، وافحص الإعدادات. خيار نشر Worker مفعّل لتكمل العملية من هنا.

زر Cloudflare الخارجي مسار بديل لمن لديه عنوان HTTPS جاهز؛ يفتح Cloudflare في تبويب جديد ولا يسجّل النشر في سجل DeskSwarm. للمسار التلقائي استخدم الخطوات أعلاه. الأجهزة والبيانات تظل على Linux.

ربط الحساب

أدخل API Token محدود الصلاحيات وAccount ID واسم Worker. يمكنك إنشاء عنوان الخدمة تلقائيًا من قسم Tunnel أدناه، أو اختبار عنوان HTTPS موجود. فعّل workers.dev للحساب. المفتاح يُحفظ مشفّرًا ولا يظهر بعد الحفظ.

إعداد Cloudflare Tunnel تلقائيًا

اختر السيرفر وخدمة DeskSwarm المكتشفة، والدومين واسم النطاق الفرعي. سننشئ Tunnel وDNS ونشغّل cloudflared على Docker دون أوامر يدوية. استخدم نفس بيانات الحساب أعلاه؛ لا تحتاج عنوان HTTPS مسبقًا. لا نستبدل سجلات DNS الموجودة.

ربط سيرفر أو اختيار جهاز NetBird

يحتاج المفتاح صلاحيات Cloudflare Tunnel Edit وZone Read وDNS Edit بجانب Workers. السيرفر الذي لا تظهر عليه خدمة DeskSwarm شغّالة يُعد غير مجهّز للنشر. إنشاء النفق يُظهر تسجيل دخول التطبيق على الإنترنت مع الاحتفاظ بكلمة المرور الحالية.

النشر والإصدارات

النشر يفعّل عنوان workers.dev عامًا مع الاحتفاظ بتسجيل الدخول الحالي. لا تفتح Docker للإنترنت. الرجوع يغيّر كود Worker وإعداداته؛ لا يسترجع قاعدة البيانات أو ملفات الأجهزة. اختَر إصدارًا يستخدم نفس خدمة Linux.
